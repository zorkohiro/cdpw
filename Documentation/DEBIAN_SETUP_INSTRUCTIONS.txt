Note that there are two variants of images we can build. One is with
an integral code_dark data filesystem on the same volume as what
we boot from and another that will have an external volume that
stores patient data.

0. Required Hardware and Environment

Get a USB flash drive of at least 8GB to put the debian 13 install image on.

Get a USB flash drive of at lesat 32GB to become the target of the install.

You can certainly user an even larger USB Key for the target of the install-
but this just makes it more painful when copying the gold master to multiple keys
for distribution. The effective size requirements are an overgenerous ~17GB
currently.

You will need to be connected to the internet to perform the following steps.

1. Copy Debian 13 iso image to the USB install image from any debian mirror.

Create the Install USB key from this with dd on a linux system or Rufus on a Windows system.

2. Create a Bootable Gold Image CDPW System

Take the install key to any reasonable recent x86_64 system and insert it. Remove all
other active boot media (disks, M2 NVMe) from it so that the install key doesn't
get confused. Make sure it is enabled for UEFI booting (not Legacy boot).

Power and and boot the install key (you'll have to hit whatever key that system needs
to ceate a one time boot menuto boot that install key- this is vendor and even model specific.
It needs to be a UEFI boot.

Once booted, select the graphical installer.

The first step prior to continuing with the installation which is waiting for input
at the first step is to insert the USB which will become the target of the install
(the new Gold Master).

You'll have to play around with navigating this installer but the first few steps
are basic keyboard and network configuration questions. Any asks for firmware for,
say, wifi, you can say no to (for now). It is not stricly necessary to have
networking up to perform this setup.

Next it will ask for a root password to be set- use 'orthanc'.
Next it will ask for a normal user's name- use 'Saruman B Orthanc'
Next it will ask for the login id- use 'orthanc' and password 'orthanc'.

Then it will spin you to the disk partitioning menu. It may ask you about
forcing UEFI (say yes).

You'll select 'manual' for partitioning. It will then print out a list of devices.
Find the target disk device- presumably it will be the only one in the 32G or whatever
size range you have the USB. That is, an internal drive is likely 250GB or
larger and the installer is like 8GB.

Fiddle around with the installation to make sure that there is a front sided
partition of ~1GB as the ESP efi boot partition (this should actually show
up mostly automatically).

Create a second partition 16GB in size, type ext4, create it, have it mount on '/' (root filesystem). Select done with this partition.
Create a third partition 2GB in size, type swap. Select done with this partition.

Select done with partitioning.

Installation should then proceed automatically for quite some time.

The 'tasksel' selection should show up- Desktop Debian, Gnome, standard utilities.

Then it will ask about installing a boot block (this only happens if you've left
your original internal drive(s) in place in this machine). Do *not* say, yes update
the primary boot device with grub - this will replace the boot stuff on the original
internal device which is probably not what you want. You want to figure out which
sd device the target Gold Master is and say you want things installed on that in
the window after this.

When the installation is done, reboot to gold master USB key.

It will come up with a standard graphical login screen for user orthanc.
You can log in with orthanc/orthanc.

6. Update and get the fixed amdgpu module unsigned kernel and install it on our system

Get a Kconsole and do 'su -' (orthanc password). Do apt update and upgrade -y. This step will
go away in the future when we settle on the correct subversion of Debian 13 to start and stay
with.

This is not the default kernel we boot. It's the kernel we use for Barco
adapters- but it requires Secure Boot to be disabled on the system we boot
from.

Follow instructions from kernel-changes for building.

Use firefox or whatever to download the image file, put it in /tmp, su to root
and apt install it.

Remove via apt all but the latest linux images. Using 'dpkg -l linux-*|grep ^ii' is a
good way of finding them.

Once done, make sure that GRUB_DISABLE_OS_PROBER is uncommented and set to true
in /etc/default/grub. then issue 'update-grub'.

Reboot to confirm the unsigned kernel is available under Advanced options.

7. Prepare for CDPW packages

There are two ways to go forward here depending upon whether you want the patient data
on the same volume as the boot key or on a second device.

For both cases, do the following

 + Get into a Konsole, su to root
 + mkdir /code_dark
 + echo '#LABEL=CODE_DARK /code_dark auto defaults 0 2' >> /etc/fstab

For the case of patient data on the same boot key:

 + Determine root device via 'df /' - the device + part number is in the 1st column.
   The root device is without the number (e.g., /dev/sda1 - root device is /dev/sda)
 + Issue the command: echo 'size=2G,type=linux' | sfdisk --append --no-reread --no-tell-kernel /dev/XXX
   (where XXX is the root device)
 + Reboot so you come up with a fresh partition table
 + Get back into a Konsole and su to root
 + Use fdisk to find the device name of the last Linux partition (which you just added)
 + Issue: mkfs.ext4 -L CODE_DARK /dev/XXX (e.g., /dev/sda4)
 + Edit /etc/fstab and remove the '#' in front of the LABEL line
 + Issue: systemctl daemon-reload
 + Issue: mount /code_dark - df should show /code_dark mounted

For the case of patient data on a separate device:

 + Make sure a device created with the mkfs.ext4 listed above gets attached to the system
 + Issue: mkdir /code_dark; echo 'LABEL=CODE_DARK /code_dark ext4 defaults 0 2' >> /etc/fstab
 + Issue: systemctl daemon-reload
 + Issue: mount /code_dark - df should show /code_dark mounted

 Note that this can just be a temporary data device- another USB key for example. The CDPW
 packages will ensure that the mounted device is correctly populated for usage with orthanc
 and cdpw.

8. Install our cdpw packages

Fetch the latest set of installable cdpw packages with firefox at https://feralsw.com/cdpw-
you want both cdpw-2*.deb and cdpw-ohif*.deb. After fetching them to Download, use Kconsole
to move them to /tmp, su to root, and install them via apt.

 + Use firefox and go to: https://feralsw.com/cdpw
 + Download the latest cdpw-*.deb and cdpw-ohif*.deb packages
 + Open a Konsole, su to root
 + Issue: rm -rf /var/tmp/packages
 + Issue: mkdir -p /var/tmp/packages
 + Issue: mv ~orthanc/Downloads/cdpw-*.deb /var/tmp/packages
 + Issue: apt install -y /var/tmp/packages/*.deb
 + Issue: rm -rf /var/tmp/packages
 + Issue: systemctl stop orthanc
 + Edit the file /usr/lib/systemd/system/orthanc.service so that the ExecStart line says:

  ExecStart=/usr/sbin/Orthanc --logdir=/code_dark/logs/orthanc /code_dark/config/orthanc

Now...

Find where code_dark_configurator and code_dark_study_tool and 'about code dark' icons
been put onto the desktop. Do a pull right menu over them and select the "Allow Launch" option.
This is an unfortunate aspect of Gnome3 that doesn't allow one to do this programmatically
at installation time.

Issue, as root, in a Konsole:

  touch /noresize

This inhibits the partition resizing. This allows you to do some validation
of this created image first.

9. Set up login screen to have the right login logo

Get a Kconsole up and and issue:
  cp /usr/share/cdpw/KaiserRedSmall.png /usr/share/images/vendor-logos.

Edit /etc/gdm3/greeter.dconf-defaults and change

 logo='/usr/share/images/vendor-logos/logo-text-version-64.png'

to

 logo='/usr/share/images/vendor-logos/KaiserRedSmall.png'

uncomment and change text on:

banner-message-enable=true
banner-message-text='Code Dark PACS Workstation Release 2.0'

Then issue: dpkg-reconfigure gdm3

10. Reboot

Log in as orthanc, get a Konsole up and issue 'systemctl status orthanc'. You should see orthanc running without errors.
Do 'ls /code_dark'- you should see:

config database logs lost+found reports

You have successfully created a key.

If you have /code_dark mounted on the same volume as this boot key,
remove /noresize. The next reboot will resize the code_dark partition
and filesystem to the rest of the available space on the disk.

If you are planning to use this key, you can then reboot. If you
are planning this to be a gold file image to create keys from,
halt the system and take this key to a linux system and plug it
in. Find out which sd device it is and use the following command
to bring in a copyable image:

dd if=/dev/sdX of=CDW_BOOT_IMAGE.img bs=1M count=20480 status=progress

The CDW_BOOT_IMAGE.img can then be written back out to other keys.
If this is a volumn with /code_dark on the same volume, the 1st
boot will resize that partiont to the length of the device you
have written to.

11. Disable software updates

sudo systemctl stop apt-daily-upgrade.timer
sudo systemctl disable apt-daily-upgrade.timer   

Edit/Create /etc/apt/apt.conf.d/20auto-upgrades and have this as content:

APT::Periodic::Update-Package-Lists "0";
APT::Periodic::Download-Upgradeable-Packages "0";
APT::Periodic::AutocleanInterval "0";
APT::Periodic::Unattended-Upgrade "0";
