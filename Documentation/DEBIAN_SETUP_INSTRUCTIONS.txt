Note that there are two variants of images we can build. One is with
an integral code_dark data filesystem on the same volume as what
we boot from and another that will have an external volume that
stores patient data.

0. Required Hardware and Environment

Get a USB flash drive of at least 8GB to put the debian 13 install image on.

Get a USB flash drive of at least 16GB to become the target of the install.

 You can certainly use a larger USB Key for the target of the install- but
 this just makes it more painful when copying the gold master to multiple keys
 for distribution. The effective size requirements are an overgenerous ~8GB
 currently (not including patient data storage).

Get a recent x86_64 system that is both UEFI and Secure Boot enabled
to use for creating the Gold image.

 Make your life less painful by opening up the system and disconnecting any
 internal storage devices (unplug sata/sata-flash or remove any NVMe cards).
 Remove or disconnect all other active boot media (disks, M2 NVMe) from inside
 it so that the install key doesn't get confused. Make sure it is enabled for
 UEFI booting (not Legacy boot). Make sure Secure Boot is enabled. If it needs
 to have USB enabled for booting, please enable it.

You will need this sytem to be on a LAN with a DHCP server and to be
connected to the internet and be able to access https://feralsw.com/cdpw
to perform the following steps.

1. Copy Debian 13.6.0 full iso image (debian-13.6.0-amd64-DVD-1.iso) to the USB
install image from any debian mirror. This image may be found at:

	https://feralsw.com/cdpw/debian/debian-13.6.0-amd64-DVD-1.iso

Create the Install USB key from this with dd on a linux system or Rufus on a Windows system.

2. Create a Bootable Initial Gold Image CDPW System

Take the install key to x86_64 system and insert it.

Power on and and boot the install key. Since the installation key should be the only
attached bootable media this should not require any additional steps on your part.

Once booted, use arrow keys to select the "Advanced options..." and hit the return key.
This brings up a second menu. Use arrow keys to select "Graphical Automated Installs"
and hit return. A bunch of screens will march along with actions being taken including
an attempt to autoconfigure networking. This should succeed if you have a valid dhcp
server on the local lan and an internet connection.

This should end at a page titled "Download debconf preconfiguration file".

At this point insert the USB which will become the target of the install
(the new Gold Master) into the system.

In the entry box presented on the screen enter "https://feralsw.com/cdpw/debian/cdpw_preseed"
and click the Continue option. The installer should do its job on the basic system install,
possibly pausing to ask you about disks (select "use entire disk" and then pick the 16GB
target device you want installed upon, and when complete it will power down the system.
When that occurs, remove the Debian Installation USB key and power on the system again to
boot up the just installed system.

It will come up with a standard graphical login screen for user orthanc.
You can log in using the password orthanc.

5. Prepare for CDPW packages

There are two ways to go forward here depending upon whether you want the patient data
on the same volume as the boot key or on a second device.

For both cases, do the following

 + Get into a Terminal, enter 'sudo su -' to become root (enter orthanc password)
 + mkdir /code_dark

For the case of patient data on the same boot key:

 + Determine root device via 'df /' - the device + part number is in the 1st column.
   The root device is without the number (e.g., /dev/sda1 - root device is /dev/sda)
 + Use 'fdisk -l ROOT_DEVICE' to find the device name of the last Linux partition
   (it should be the second of two marked 'Linux Filesystem')
 + Issue: mkfs.ext4 -L CODE_DARK /dev/XXX (e.g., /dev/sda4)
 + echo 'LABEL=CODE_DARK /code_dark auto defaults 0 2' >> /etc/fstab
 + Issue: systemctl daemon-reload
 + Issue: mount /code_dark - df should show /code_dark mounted

For the case of patient data on a separate device:

 + Make sure a device created with the mkfs.ext4 listed above gets attached to the system and unlocked
   (if needed). You should have received it already correctly formatted and labeled if this is the
   Apricorn secure storage device.
 + Verify its existence by issuing in Terminal as root the command 'blkid|grep CODE_DARK'. If anything
   other than one device shows up, stop and go no ruther.
 + Issue: echo 'LABEL=CODE_DARK /code_dark ext4 defaults 0 2' >> /etc/fstab
 + echo 'LABEL=CODE_DARK /code_dark auto defaults 0 2' >> /etc/fstab
 + Issue: systemctl daemon-reload
 + Issue: mount /code_dark - df should show /code_dark mounted

 Note that this can just be a temporary data device- another USB key for example. The CDPW
 packages will ensure that the mounted device is correctly populated for usage with orthanc
 and cdpw.

6. Install our cdpw packages

Fetch the latest set of installable cdpw packages with firefox at https://feralsw.com/cdpw-
you want both cdpw-2*.deb and cdpw-ohif*.deb. After fetching them to Download, use Terminal
to move them to /tmp, su to root, and install them via apt.

 + Use firefox and go to: https://feralsw.com/cdpw
 + Download the latest cdpw-*.deb and cdpw-ohif*.deb packages
 + Open a Terminal, 'sudo su -' to root.
 + Issue: apt update
 + Issue: rm -rf /var/tmp/packages
 + Issue: mkdir -p /var/tmp/packages
 + Issue: mv ~orthanc/Downloads/cdpw-*.deb /var/tmp/packages
 + Issue: apt install -y /var/tmp/packages/*.deb
 + Issue: rm -rf /var/tmp/packages
 + Issue: systemctl stop orthanc
 + Edit the file /usr/lib/systemd/system/orthanc.service so that the ExecStart line says:

  ExecStart=/usr/sbin/Orthanc --logdir=/code_dark/logs/orthanc /code_dark/config/orthanc

Now...

Find where code_dark_configurator and code_dark_study_tool and 'about code dark' icons
been put onto the desktop. Do a pull right menu over them and select the "Allow Launch" option.
This is an unfortunate aspect of Gnome3 that doesn't allow one to do this programmatically
at installation time.

Issue, as root, in a Terminal:

  touch /noresize

This inhibits the partition resizing. This allows you to do some validation
of this created image first.

9. Set up login screen to have the right login logo

Get a Terminal up and and issue:
  cp /usr/share/cdpw/KaiserRedSmall.png /usr/share/images/vendor-logos.

Edit /etc/gdm3/greeter.dconf-defaults and change

 logo='/usr/share/images/vendor-logos/logo-text-version-64.png'

to

 logo='/usr/share/images/vendor-logos/KaiserRedSmall.png'

uncomment and change text on:

banner-message-enable=true
banner-message-text='Code Dark PACS Workstation Release 2.0'

Then issue: dpkg-reconfigure gdm3

Disable upgrade timers:

sudo systemctl stop apt-daily-upgrade.timer
sudo systemctl disable apt-daily-upgrade.timer   

10. Reboot

Log in as orthanc, get a Terminal up and issue 'systemctl status orthanc'. You should see orthanc running without errors.
Do 'ls /code_dark'- you should see:

config database logs lost+found reports

Issue as root: rm -f /noresize

You have successfully created a Gold Image master key.
